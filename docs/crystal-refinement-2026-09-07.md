# Crystal rejection investigation and backend refinement

The investigation covered the full retained rejection journal: 1,311 distinct records and 3,065 occurrence events at the fixed audit snapshot. It parsed every occurrence and grouped recurring failures, then inspected representative source/candidate pairs and actual model traces. These are rejection records, not all generation attempts, so they cannot establish a station-wide rejection rate. The screenshot's pending count is a review backlog, not a count of lost spoken lines.

The [corpus audit](rejection-corpus-audit.md) and [prompt audit](crystal-prompt-audit.md) retain the detailed evidence. The JSON corpus report identifies a consistent private SQLite snapshot and exact event IDs. Historical records, votes and original source files remain intact.

## What caused avoidable failures

| Finding | Backend correction |
| --- | --- |
| Four old failed source families were captured 1,162 times, often with their actual candidate missing, during deferred repair visits. | Retain the latest attempted wording separately from accepted text. Persist a source/candidate/evaluation digest and review pointer so the same deferred failure does not create another notification. |
| 128 of 165 discarded model-fragment events contained slash-separated bars, but a generic prose handler demanded a finished sentence. | Preserve complete tint output, line breaks and numbered bars for the tint parser. Genuine token exhaustion or output overflow retains full evidence and fails explicitly; no clipped prefix is installed. |
| Round and repair prompts demanded contradictory formats. Some caller repairs lost the requirement to rhyme. Failed wording was usually omitted from the next request. | Use shared first-attempt and repair builders with one output format, complete original facts, full supplied style passages, the actual failed attempt and detailed evaluation. Facts and conversational roles precede style. |
| Whole-round output had only source length plus 400 characters, far below the expansion allowed per turn. | Plan ordered batches under the configured reply cap, with room for rhyming bars. Preserve completed positions on deferral. Single unlabelled lines use a single-line prompt; whole-only live work stays within one request. |
| Equivalent apostrophes, possessives, written quantities and some ordinary grammar produced false obligations. Old quantity handling could also permit the wrong values. | Share normalized name/quantity/question/negation contracts between writer and grader. Preserve exact counts, times and polarity; distinguish pronominal “one,” equivalent “the one/only thing,” and imperatives such as “do it yourself!” from real numeric or question obligations. |
| Transcript-repair instructions had entered cached source passages. | Filter only exact known instruction echoes before source selection and at harvest. Log removed harvest spans. Preserve original caches and quoted, embedded or ambiguous wording. |
| A caller could lose structural turns and be described as complete because enough other lines passed, only to fail later in the pipeline. | Keep incomplete callers pending with their accepted progress intact. Repair missing turns before handing the complete call to recording. |
| The ad brief missed an expected product with sale wording such as “sign up” or “pay through.” | Supplement the existing brief check with expected product identity plus an affirmative sale action. A bare sale verb or unrelated product does not qualify through this addition. |

Crystal generation also uses bounded rewrite temperature instead of adding station heat and surplus variation to strict repair requests. Grader version 5 keeps the existing configured strength, anchor floors, rhyme requirements and coverage policy. Coverage metadata remains version 4 because its structural format did not change.

The rejection workbench's generated trials use the same production repair builder and output plan. Each saved trial records prompt version 2 and grader version 5. Older trials must be rerun before applying against the changed backend. Trials preserve source/evaluation evidence and do not themselves approve, record or play wording.

## What this does not establish

The source cleaner deliberately leaves ambiguous fragments for inspection. Deterministic content and spelling-based rhyme checks remain imperfect: a machine pass does not prove every proposition or spoken rhyme is correct. The retained examples include actual changed facts, missing caller introductions and unsupported new imagery that should still require repair.

The semantic-only [replay](rejection-contract-replay.json) uses a frozen union of retained style vocabulary, an approximation to the historical live vocabulary. Its changed subcheck results are not complete acceptance decisions. Full integrated replay and bounded live trials are reported separately so those denominators cannot be mistaken for a station-wide improvement rate.

## Validation

The final complete backend suite passed **733 tests in 24.564 seconds** with isolated data and bytecode-cache directories. Tests include actual wrappers around fake model replies, exact candidate retention, repeated admission deferral, ordered batch resume and fairness, whole-only budgets and cached revalidation, product-aware brief checks, preserved review decisions and the production prompt used by workbench trials. The earlier 709-test and 719-test runs describe intermediate deployments. Desktop packaging includes all seven support modules needed by these features.

The [integrated replay](crystal-integrated-replay.json) ran the actual current grader against all 920 nonempty tint occurrences, using an isolated preview context and guarding against model calls or production review writes. Of these, 906 had an explicit historical machine verdict; 14 stayed unrecorded rather than being counted as improvements. There were 131 newly passing occurrence events, representing 101 distinct source/candidate pairs at their latest occurrence. This is **a change in machine verdicts, not 101 verified editorial fixes**. Manual inspection found residual false passes, including a feeling becoming a plan, an invented store-bar location, and an invented ending to an unfinished source. The shared prompt now explicitly addresses these errors; historical wording was not bulk-approved.

## Findings from the first live deployment

The [eight live rewrite trials](crystal-rewrite-benchmark.json) used exact saved pending occurrences across caller, gallery, ad, banter, manager, news and an unspecified road. Each made one request through the workbench with the deployed prompt and grader. Four passed the machine checks and four failed. Manual inspection found unsupported additions or awkward filler in machine-passing output too; this is not four certified repairs or a station-wide pass rate. The original request, source, candidate, full evaluation and wire trace remain inspectable, and none was applied.

Those trials and the [production observation](crystal-refinement-production.json) exposed three further implementation defects:

- Whole-only rewrites retained slash bar separators, while the track-talk fidelity gate refused multiple slashes. The whole path now uses the same speech cleanup as individual turns, preserving original speaker order and raw wire evidence.
- Rhyme segmentation stopped recovering comma-separated bars whenever a candidate contained two sentences. An opening question could therefore hide all following bar ends after speech cleanup. The revised parser recovers clauses within each sentence, retaining short fragments and word order. The actual gallery example now retains scream/stream and visible/indivisible evidence but still fails its separate transformation check.
- A real production request carried 63,690 user-prompt characters for 2,711 original dialogue characters. Its conversation payload included 39,515 characters of rejected-attempt data and 14,088 of source contracts. Most was repeated metadata, instructions or escaping; all twenty requested rejected candidates in that particular call were empty. This motivated compact structured facts and relevant failure evidence, with full original wording and supplied style retained.

The long trial's latency was traced to **140.775 seconds waiting for admission and 9.197 seconds on the model HTTP request**. The preceding production request itself took 132.4 seconds: 16,026 prompt tokens, 33.49 seconds prefill and 96.13 seconds decoding 572 tokens. The queue advanced normally; this was a large request occupying the model lane, not a stuck callback. These are observed timings, not a promised latency bound.

During the first five-minute observation, eight of eight production wire requests used the shared prompt, eighteen deferred finishes caused no repeated same-parent/candidate refusal group, and one new XTTS recording had a matching positive synthesis receipt for 13.9 seconds. Ready stock stayed at 34; sampled accepted work waiting for recording was zero. This confirms active writing/recording and the absence of the reproduced notification burst in that window, not a measured improvement in stock or overall throughput.

## Further repair trials and the remaining quality problem

The compact prompt reconstruction reduced that exact 63,690-character request to **15,966 characters, a 74.93% reduction**. Every original turn, full supplied style passage, world, requested turn and factual contract remained present. Tests also cover nonempty rejected candidates and concrete fault details, so compaction is not limited to the empty-candidate example. See the [measured reconstruction](crystal-prompt-size-check.json).

Four [targeted second attempts](crystal-rewrite-second-pass-review.json) received explicit feedback about the first drafts' actual errors. Three passed the machine checks, compared with two of those same four on their first attempts. **None was an unqualified clean editorial repair.** One ad restored which object had value and what the light caught, but still contained broken filler. A short question still lost its past-tense wording and added an action. A request to explain an unspecified remainder invented what that remainder referred to. The gallery rewrite now correctly received rhyme credit, while still failing its independent transformation requirement. These are selected retries, not an independent cohort or a station-wide quality estimate.

The shared prompt now explicitly preserves predicate ownership, tense, location and time relationships, uncertainty, unfinished source material and the scope of unspecified words such as "rest." It asks the writer to recast syntax and verbs around those facts, rather than inventing an extra fact to supply a rhyme. Those instructions address observed errors; the trials show that the model does not reliably obey all of them. Lexical meaning checks can miss changed propositions even when enough original words remain. A lower rejection count would therefore be insufficient evidence of success.

The deployed model advertises thinking support, but normal station calls disable it. Two paired [reasoning diagnostics](crystal-reasoning-benchmark-review.json) used exactly the second attempts' messages with thinking enabled and a larger, 768-token combined output budget. Both spent that entire budget before producing any final wording: approximately 113 and 117 seconds decoding, with empty final content. Their full wire traces remain available as failed diagnostic operations. This does not measure reasoning quality with an adequate budget; it establishes that this bounded configuration does not solve the problem and consumes considerably more model time. Normal production still uses its existing non-reasoning mode. Explicit `reasoning: true` is available only as an optional workbench `/try` request field; it does not change persistent settings.

## Model time, queue fairness and recording

The [follow-up production observation](crystal-refinement-followup-production.json) confirmed compact structured contracts on actual requests. A 4,414-input-token request still took 162.8 seconds, including 152.1 seconds decoding 897 tokens. Compacting input fixes avoidable prefill work; it cannot eliminate long output generation. In the same observation, the 31B model was reported entirely in GPU memory, the large Ollama runner dominated sampled GPU activity, and current thermal/power throttle flags were inactive. A smaller model was concurrently active. These samples support GPU-resident decoding as the observed bottleneck, without establishing a hardware maximum or ruling out every other contribution.

Ordinary first-pass and repair groups now plan against **1,800 output characters**, or the user's lower cap. Each batch retains the complete source context and original indices; accepted turns survive deferral. An oversized individual repair can still use the user's full existing cap rather than being clipped or discarded. Smaller requests release the existing model queue between groups. They improve scheduling opportunity; they do not impose a wall-clock deadline or guarantee shorter total generation time, since each group still needs context. Six new wrapper regressions cover these cases alongside the full suite.

Across the recorded checkpoints, ready stock increased from 34 to 35 while 76 items still awaited tinting; sampled accepted recording debt was zero. The verified 13.9-second fresh synthesis belongs to the first observation. A later file update alone was not counted as a new uncached render. These measurements point to unfinished writing/tinting work as the sampled preparation backlog, while showing that recording can complete accepted work. They do not establish that all scheduling or writing throughput problems are resolved. The final deployment and its bounded live checks are retained in [validation](crystal-refinement-final-validation.json) and [production evidence](crystal-refinement-final-production.json).

The bounded final observation captured seven real production wire requests using the shared prompt and normal non-reasoning mode. Six grouped requests asked for three to seven turns within 750–1,703 output characters. Six completed calls took 6.28–31.44 seconds of service, with 6.52–37.40 seconds of observed queue wait. These are different workloads from the earlier large request, so this is evidence that the new batching runs and the queue advances, not a controlled speed comparison. Twelve new refusal events included eleven tint evaluations at grader version 5; there were no same-parent/candidate recaptures and no slash vetoes. Ready stock was 38 and awaiting-tint stock 75 at both final snapshots; accepted recording debt was zero. No new uncached synthesis was verified in this short window.

The twelfth refusal, event 3496, was a non-tint 5,002-character response with no sentence punctuation, slash bars or line breaks, beginning mid-word and ending unfinished. The existing prose guard reported "no finished sentence." It did not repeat the repaired bar-format defect. Its retained record has no matching token-limit receipt, so this investigation does not label it proven token exhaustion. Some failures still have incomplete diagnostic evidence, as well as actual unfinished wording.

This investigation cast no review votes, applied no trial wording, changed no acceptance settings and requested no playback. The station's enabled, paused state was preserved through the backend updates. Rejection history remains available for inspection rather than being cleared to make the counter look better.
