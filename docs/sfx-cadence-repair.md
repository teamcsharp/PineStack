# Recorded SFX cadence and character participation

The main live path explicitly suppressed both samples and the SFX character whenever a conversation was prerecorded, had a caller, or used continuous talk. Consequently, a sample rate of 100% and character participation of 80% could still yield neither. The character's old fallback also did model rewriting and synthesis while holding the microphone; simply removing the suppression would add delays to prepared conversations.

The new `sfx_every_units` setting plans a cached random sample after every N host units; zero keeps legacy random timing. A unit is a completed recorded DJ/cohost/third/host segment. When a prerecorded reply has no reliable internal sentence boundaries, its entire clip remains one unit. Caller, soundboard, and SFX-character rows do not increment the host counter. `sfxguy_every_units` independently controls opportunities for a prepared character take (default four), with the existing participation rate applied at those opportunities. The master SFX switch still applies. Cadence timing replaces the legacy rate/gap dice; sample duration limits, bans, weights, and configured drop-family filtering still apply.

The sample pool is read from its existing background cache, with at most 64 file probes per draw. This path does not scan the network share. The requested collection is mounted at `/samples/samples_grabbed`, corresponding to the actual `QuickSwap\samples_grabbed` share family; the previously described `samples\_grabbed` spelling did not match the discovered share. Samples retain a separate soundboard row, and the character retains `who=drop`, its exact configured voice, and its recorded words.

Original speech paths, order, text, and voices remain unchanged. Optional samples and character takes are added during audio assembly; they cause no model request or speech synthesis. The entire original burst is budgeted before additions. If a slower assembly exhausts an optional allowance but the original speech still fits, one additional concat removes the optional media and keeps the original takes. No speech is truncated to make room. A missing sample, unavailable prepared character, or tight programme slot can leave a cadence opportunity unfilled.

`sfx_cadence.sqlite3` stores completed audible row receipts. Planning, queued media, muted playback, failed hardware delivery, and skipped browser intervals do not increment the counter. Page and verified hardware completion share row identities, so two output copies count once. Prepared character reservations commit only after their own audible completion; known prepublication failures release them. The normal held-audio replay keeps the same receipt metadata. The authenticated `/api/sfx/stats` response exposes durable heard counts alongside due/omitted opportunity counts for the current process. Sample play statistics also update from the completed receipt.

Intentional Nabu mute is read from the level captured at dispatch. Its transport completes normally and consumes delivery ownership, but it creates no audible host/sample/character, repetition, or source-completion credit. This avoids treating an operator mute as a device failure. An independently audible page copy still earns its own receipt once. Current slider values cannot retroactively change whether an earlier dispatch was audible.

Live observation then identified an additional bypass: emergency continuity host pairs used their own playback path, so those actual DJ replies neither advanced the cadence counter nor received samples. `continuity_air` now uses the same additions and receipt helpers. Its existing two-host selection, fallback eligibility, 60-second spacing, and unresolved tint debt remain intact. Original decoded PCM is copied byte for byte in the original order; only cached optional media is decoded separately. Optional additions must fit a 30-second total, while an already longer original pair remains whole. Missing or over-budget additions leave the core conversation intact. Failed hardware delivery now persists the exact assembled clip and row windows through the existing held-audio queue as well as retaining page rescue.

The final continuity checks passed 18 tests in 0.752 seconds: ten existing checks plus eight new cases covering real FFmpeg decoding and original PCM equality, second-host sample/fourth-host character placement, actual page ACK and hardware deduplication, missing optional media, pause/off-air cancellation, intentional mute, held delivery, and the optional duration bound. No production models, synthesis, playback, settings, or votes were invoked by these tests. The direct-route audit found only historical resume reels as another multihost bypass; archived reels are not decorated again. Live postdeployment receipt confirmation remains a separate check.

Focused checks cover durable restart/idempotency/concurrency, exact strict-stream ordering and voice identity, sample-family/bans/duration selection, bounded broken-pool probing, receipt boundaries and muted/skipped intervals, source-credit preservation, slot budgeting, late optional-overrun removal, and refusal cleanup. The standalone path additionally checks a real three-tone concatenation. The focused SFX suite passed 46 tests, followed by all 14 stream cadence checks including the added held-mute regression; nine existing strict-ready checks also passed. Deployment settings and live hearing verification belong to the coordinating agent; this implementation work did not change live settings, volume, playback, or editorial decisions.
