# Pine Box LCD agent

Tap a **CUT** line in Behind the scenes to review it on the display. **Words** shows the complete rejected and original wording; **Why** shows the responsible gate, reasons and recorded evaluation; **System** shows the workflow, saved context and decision effect. Previous/Next page buttons handle long records. Tap outside the popup or Close to dismiss it. The native AV/PB corner remains available.

**Accept wording** saves an individual approval and sends the retained work through the orchestrator's recovery checks. **Reject wording** keeps the cut and withdraws recovery that is still waiting to be recorded. Neither button directly plays or replays audio. A saved decision can be reversed using the other button. Individual editorial decisions become bounded examples in future writing/tint prompts; one-time batch approvals do not become preference examples, and feedback does not automatically alter acceptance thresholds or repair technical failures.

New cuts retain their exact review ID and occurrence number before entering the cupboard. The popup checks that occurrence and the current revision before submitting feedback. A newer occurrence makes old evidence read-only. Older cupboard cuts that lack an unambiguous retained record remain visible with an explanation and disabled decisions; the app does not guess their wording or parent programme.

The desktop's **LCD** icon locates Quanta displays over Wi-Fi or USB. Network discovery reads `/status` using mDNS and a bounded scan of attached private subnets. USB discovery lists supported ESP32 bridges and excludes the Reachy robot. Select a result, connect, and start. USB uses one persistent 921600-baud connection. Pine protocol 2 uses an identity-checked persistent binary TCP connection on port 3233; legacy firmware uses base64 JPEG HTTP posts. There is one frame in flight at a time, and only a matching draw acknowledgment counts as a delivered frame.

Legacy CYD HTTP/USB frames retain their **12,288 JPEG-byte** limit. The protocol 2 binary transport advertises **24,576 bytes** and bypasses the HTTP parser's base64/String copies. Native 320×240 pixels are preserved. The encoder reuses its last successful JPEG quality, reduces it only as needed to fit, and recovers quality gradually on simpler screens. Diagnostics record frame bytes, wire latency and the firmware's combined decode/SPI time. The producer schedules against a 30 Hz target without adding the old 200 ms delay after every ACK; actual delivered cadence is limited by the CYD and current network.

Swipe down from the top edge to open quick controls. The eight icons select Newspaper only, Pine gallery, Paper + chat, Tabloid, Chat overlay, Auto-scroll, Quanta avatars and Screensaver. Swipe up closes the drawer. A short top-left tap still switches Pine/Quanta immediately. The desktop LCD panel also offers Live dialogue only, Behind the scenes, slideshow duration and the screensaver timer/preview.

The newspaper scrolls continuously with optional foreground booth dialogue. It follows new issues automatically until an older issue is selected. Middle left/right taps browse issues. Tap a dialogue bubble, then Favorite or Download. Favorites use the station's saved-dialogue collection; downloads use the desktop's remembered sound-sample folder. A message identifies when only surrounding broadcast audio was available. Closing the LCD panel keeps the producer running; “Resume on app launch” reconnects the remembered device. A physical identity change stops automatic connection. When the station is paused, the optional behind-the-scenes view shows current station preparation.

Choose **Newspaper only** for the ordinary paper without chat or the automatic paused view. **Pine Box gallery · images only** shows the existing image gallery as a shuffled slideshow, with randomized transitions and no newspaper or chat overlays. The default hold is eight seconds per picture; **Each picture** changes it from three seconds to one minute. **Cycle newspaper / gallery** alternates these two views. **Next gallery image**, or a tap on the right side below the corner header, advances the picture. The AV/PB switch remains available, and the Quanta avatar slideshow remains separate.

The gallery uses the same authenticated image feed as Pine Box, excluding newspaper snapshots and video files. It preloads images at display size and retains only the current and next picture. Static pictures use a one-second frame heartbeat; transitions use the normal acknowledged frame cadence. Opening Quick Settings pauses the slideshow transition until the drawer closes.

The current speaker appears immediately from `speaking_now`, and coalesced broadcasts follow `stream_now` turn boundaries against the station clock. The active turn takes priority on the canvas, beginning at its first text line. Completed dialogue, recorded text awaiting playback, and other booth activity carry distinct labels. Pending and nonaudio entries remain visible but cannot save an audio sample. The station refreshes once a second; known round boundaries advance between polls.

## Quanta avatars and Pine Box on the same firmware

Pine's compatible firmware keeps Quanta's existing JPEG, serial, animation and SD-gallery commands. **The top-left AV / PB button switches between the existing avatar slideshow and Pine Box without rebooting or swapping firmware.** AV opens avatars; PB returns to Pine Box. The display remembers that choice across power cycles. On the native 320×240 CYD, the button occupies a dedicated 64×60 corner region, with a 56×48 visible target inset four pixels from the edge. Newspaper, dialogue and Quick Settings leave that region clear. Firmware protects it from incoming JPEG and avatar draws, and corner input takes priority over drawer controls. While avatars are selected, the Pine producer keeps listening for input but sends no frames. Quanta remains usable, including gallery uploads and playback.

A renewable 15-second touch lease suppresses Quanta's conflicting gamma, transport and corner gestures while Pine is driving the screen. The lease expires if Pine goes away, restoring normal Quanta controls. The top-left mode switch remains available. On legacy firmware, the app can stream immediately, but installing compatible firmware enables the complete local mode switch and touch behavior.

USB is an exclusive serial connection. **Release USB to Quanta** returns the display to avatars and closes Pine's serial bridge so Quanta can connect; **Start** reconnects Pine. For simultaneous use, connect Pine Box over Wi-Fi and Quanta over USB. The on-device top-left switch does not require reflashing. Live Pine content requires the desktop to be running, while the stored avatar slideshow runs by itself.

## Building and installing

Expand **Program and manage the display**. Choose the exact board, enter the display's Wi-Fi network, and build. An isolated copy under `%APPDATA%\pinebox-desktop\lcd-firmware\build-source` receives the small Pine compatibility patch; `C:\_tools\Quanta` is left intact. The original Quanta Arduino scripts install their toolchain when needed. Each build has a board, device identity when known, SHA-256 and timestamp. Modified or mismatched binaries cannot be installed.

For USB installation, find and identify the selected COM port first. Identification briefly resets that display. The programmer rechecks its immutable MAC, backs up the full flash, then installs the matching build. A disappearing COM port never falls back to a different attached device. Existing external SD avatars are retained. Wi-Fi installation uses Espressif's `espota` protocol on port 3232; Quanta v49 or newer and an actual OTA partition are required. Profiles such as `huge_app` cannot use OTA. Connect/test after the reboot verifies the firmware and identity before resuming.

The compatible source advertises `pine=1`, `pineproto=2`, `stream=3233`, `maxjpg=24576`, `gesture=1`, `display=pine|avatar`, `saver=0|1`, `idle=<seconds>`, and its MAC on network and USB status. Network status also reports actual CPU MHz and Wi-Fi power-save mode. Ordinary Quanta commands remain unchanged.

| Pine command | Behavior |
| --- | --- |
| `QCMD PINEMODE <0 or 1>` | Explicit avatar/Pine choice, remembered across reboot. |
| `QCMD PINELEASE 15` | Renew Pine touch ownership; does not reset inactivity. |
| `QCMD PINEIDLE <0 or 15..3600>` | Disable or arm the device's physical-input inactivity timer. |
| `QCMD PINESAVER <1 or 0>` | Preview temporary avatars or wake back to Pine. |

The idle timer runs on the LCD, independent of renderer timing. Frames and lease/status polls do not count as physical activity. An automatic screensaver uses the existing SD avatars without changing the remembered manual view. Any contact wakes Pine and consumes the entire contact, preventing an accidental favorite/download. Manual avatar selection remains manual. Turning off an armed automatic screensaver returns to Pine.

Protocol 2 input uses `SWIPE down|up x y`, `TOUCH tap x y`, `PINEMODE pine|avatar`, `PINESAVER 1` and `PINEWAKE` events. Gesture detection waits for release so a swipe cannot also activate a button. CYD contact samples are buffered every 20 ms during JPEG callbacks using the separate touch pins; gesture dispatch happens after drawing, without reentering the TFT driver. The app renews the touch lease and checks the remembered device identity/mode while avatars are running, even though no host frames are sent.

Binary frames start with `PJF1`, a big-endian 32-bit sequence and a big-endian JPEG length, followed by the exact JPEG bytes. The server's initial `PINEFRAME 2` response must match the previously verified MAC. A matching `QACK img ... seq=...` follows drawing. Partial bodies time out, oversized bodies are rejected, and only one producer owns this socket. Closing it frees its input buffer.

On CYD units whose existing gallery skipped Quanta's calibration screen, the compatibility patch maps the resistive controller's raw range into screen pixels and follows display rotation. Saved calibration is respected. The top-left zone is excluded from native gallery navigation. OTA upload progress feeds Quanta's watchdog so a normal update lasting over 20 seconds does not trigger a restart.

## Stable native corner switch on 2026-09-07

The CYD corner compositor owns the full 64 by 60 pixel region throughout JPEG decoding, including SD avatar frames and letterbox clears. It clips decoder tiles around that region, preserving each source row stride. The AV/PB badge is redrawn only after an explicit clear, dimension change or mode change. The native Quanta top-left rotate marker is removed; copy status is contained to the right, and cosmetic touch ripples that would intersect the corner are suppressed. This prevents competing overlays from erasing or flashing over the mode switch. Boards using a framebuffer repaint the badge after their flush; continuous pixel protection during each decoder callback is verified for the attached CYD direct-draw path.

Touch calibration and orientation are unchanged by this correction. Corner releases emit a diagnostic `PINECORNER x y raw rx ry cal=N rot=N` event on XPT2046 boards, alongside the mode event; this diagnostic does not trigger a second host action. Tap the centre of the visible badge, around `(32,28)` on this display. A screensaver wake still consumes the contact, and swipe detection remains release based.
