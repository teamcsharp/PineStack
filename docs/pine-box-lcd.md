# Pine Box LCD agent

The desktop's **LCD** icon locates Quanta displays over Wi-Fi or USB. Network discovery reads `/status` using mDNS and a bounded scan of attached private subnets. USB discovery lists supported ESP32 bridges and excludes the Reachy robot. Select a result, connect, and start. USB uses one persistent 921600-baud connection; Wi-Fi uses acknowledged base64 JPEG posts. There is one frame in flight at a time.

CYD frames are limited to **12,288 JPEG bytes**, because Quanta's HTTP parser retains multiple copies of the base64 body in its small heap. The encoder starts at JPEG quality 0.66 and reduces quality only as needed to fit, keeping the native 320×240 dimensions. The transport rejects an oversized frame before sending it and records the actual payload size in diagnostics. A dense image fixture fell from 38,525 bytes to 12,231 bytes at quality 0.17 without resizing; ordinary simpler frames retain higher quality.

The two Pine layouts are a dim, endlessly scrolling newspaper with prominent booth dialogue, and dialogue alone. The newspaper follows new issues automatically until an older issue is selected. Middle left/right taps browse issues. Tap a dialogue bubble, then Favorite or Download. Favorites use the station's saved-dialogue collection; downloads complete directly into the desktop's remembered sound-sample folder. A message identifies when only surrounding broadcast audio was available. Closing the LCD panel keeps the producer running; “Resume on app launch” reconnects the remembered device. A physical identity change stops automatic network reconnection.

The current speaker appears immediately from `speaking_now`, and coalesced broadcasts follow `stream_now` turn boundaries against the station clock. The active turn takes priority on the canvas, beginning at its first text line. Completed dialogue, recorded text awaiting playback, and other booth activity carry distinct labels. Pending and nonaudio entries remain visible but cannot save an audio sample. The station refreshes once a second; known round boundaries advance between polls.

## Quanta avatars and Pine Box on the same firmware

Pine's compatible firmware keeps Quanta's existing JPEG, serial, animation and SD-gallery commands. **The top-left corner switches between the existing avatar slideshow and Pine Box without rebooting or swapping firmware.** The display remembers that choice across power cycles. The tiny PB/AV indicator names the other view. While avatars are selected, the Pine producer keeps listening for input but sends no frames. Quanta remains usable, including gallery uploads and playback.

A renewable 15-second touch lease suppresses Quanta's conflicting gamma, transport and corner gestures while Pine is driving the screen. The lease expires if Pine goes away, restoring normal Quanta controls. The top-left mode switch remains available. On legacy firmware, the app can stream immediately, but installing compatible firmware enables the complete local mode switch and touch behavior.

USB is an exclusive serial connection. **Release USB to Quanta** returns the display to avatars and closes Pine's serial bridge so Quanta can connect; **Start** reconnects Pine. For simultaneous use, connect Pine Box over Wi-Fi and Quanta over USB. The on-device top-left switch does not require reflashing. Live Pine content requires the desktop to be running, while the stored avatar slideshow runs by itself.

## Building and installing

Expand **Program and manage the display**. Choose the exact board, enter the display's Wi-Fi network, and build. An isolated copy under `%APPDATA%\pinebox-desktop\lcd-firmware\build-source` receives the small Pine compatibility patch; `C:\_tools\Quanta` is left intact. The original Quanta Arduino scripts install their toolchain when needed. Each build has a board, device identity when known, SHA-256 and timestamp. Modified or mismatched binaries cannot be installed.

For USB installation, find and identify the selected COM port first. Identification briefly resets that display. The programmer rechecks its immutable MAC, backs up the full flash, then installs the matching build. A disappearing COM port never falls back to a different attached device. Existing external SD avatars are retained. Wi-Fi installation uses Espressif's `espota` protocol on port 3232; Quanta v49 or newer and an actual OTA partition are required. Profiles such as `huge_app` cannot use OTA. Connect/test after the reboot verifies the firmware and identity before resuming.

The compatible source advertises `pine=1`, `display=pine|avatar`, `ota=0|1`, and its MAC on both network and USB status. `QCMD PINEMODE 0|1` selects the view; `QCMD PINELEASE 15` leases Pine touch input; `PINEMODE` input events notify the desktop of a corner tap. Ordinary Quanta commands remain unchanged.

On CYD units whose existing gallery skipped Quanta's calibration screen, the compatibility patch maps the resistive controller's raw range into screen pixels and follows display rotation. Saved calibration is respected. The top-left zone is excluded from native gallery navigation. OTA upload progress feeds Quanta's watchdog so a normal update lasting over 20 seconds does not trigger a restart.

## Validation and recovery

Run `node --test tests/test_lcd_agent.cjs` for identity, acknowledgment, reconnect, mode switching, source patch and sample-saving coverage. `tools/lcd-ui-smoke.cjs` runs a hidden Electron preview and writes screenshots/result JSON to `%TEMP%\pine-lcd-ui-smoke`. PowerShell workers are materialized outside `app.asar`, allowing the packaged desktop to run them.

For a bounded observation of the normal running desktop, launch once with `PINE_DESKTOP_PLAYBACK_PROBE=1`. It records existing media playback state, queue timing and LCD acknowledgment counters under `%TEMP%\pine-desktop-playback-probe`, then stops after three minutes. It opens no debug port, writes no station controls, excludes signed media query strings and saves only the last actually acknowledged LCD JPEG for visual inspection. The flag is consumed for that launch.

`node tools/lcd-package-smoke.cjs <local-electron.exe>` verifies worker extraction from an actual `app.asar`. `electron tools/lcd-device-smoke.cjs --host=<IP-or-COM> --identity=<MAC>` is an explicit physical test: it reads the station's current newspaper, sends acknowledged JPEG frames, and verifies avatar/Pine mode transitions. It changes only the specified display's active view. The regular `pine_box.exe` launcher copies the shared desktop into the persistent local runner on every launch, so these controls survive normal app restarts.
